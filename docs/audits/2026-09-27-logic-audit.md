# Проверка логики перед отправкой, 27 сентября 2026

Проверены пути observe → interpret → present, выбор позиции, правила Bet / Hedged / Book, неполные ответы источников и повторная интерпретация сохранённых результатов. Доступность сайта сама по себе не подтверждает корректность этих правил.

## Воспроизведённые ошибки и исправления v6

1. **Баланс портфеля ошибочно доказывал хедж выбранной позиции.** Контрольный пример: BTC long $10M + BTC short $10M + выбранный ETH short $1M. Старый код выдавал Hedged по 95% взаимного погашения всего портфеля. Теперь встречные perpetual-позиции дают Unknown: суммарная экспозиция этих позиций вместе со spot не моделируется. В том числе 100% spot-покрытия само по себе больше не доказывает нейтральность при наличии встречной perp-позиции. Это проверка допустимых входных данных, а не утверждение, что такой конкретный портфель найден в production.
2. **Неудачный поиск фандеров превращался в нулевое покрытие.** При полном чтении собственного адреса и ошибке чтения баланса найденного фандера результат был Looks like a bet. `linkedHedgeCoverage` теперь доходит до обоих правил Bet. Partial / missing дают Unknown. Материальные активы фандера по-прежнему не считаются собственным хеджем.
3. **Известное обязательство оставалось лишь примечанием.** Отрицательный spot-баланс в активе выбранной позиции мог сосуществовать с уверенным Bet либо spot-only Hedged. Теперь наблюдение schema 6 записывает `hasUnresolvedLiability`, и такой случай даёт Unknown. Долг в другом активе остаётся контекстом. Повреждённая строка spot-баланса также блокирует Bet для long: она могла скрыть обязательство.
4. **Непроверенный HIP-3 актив принимался за отсутствие совпадающего spot.** Для `xyz:ETH` реестр не устанавливает соответствие с ETH/WETH. Теперь без подтверждённой идентичности базового актива ответ Unknown. Наблюдаемые двусторонние заявки в самом этом рынке по-прежнему могут дать Book: это отдельный факт об активности.

Исходные ошибки сначала воспроизведены пятью падающими проверками; затем исправлены. Новые тесты также проверяют обе ветки Bet, неполные данные, известный долг при разных коэффициентах покрытия, сохранение Book и корректные обычные хеджи.

## Согласованность результатов

- Правила имеют версию v6, новые наблюдения — schema 6. Ключ кеша включает версию правил.
- Диаграмма отмечает неразрешённую экспозицию; такой коэффициент не попадает в рейтинг минимального покрытия как полноценное измерение.
- Четыре примера от 26 сентября повторно интерпретированы без API-запросов. Их вердикты и публичные ссылки сохранились. `snapshotClassifierVersion` сохраняет версию, из которой был получен исходный ID.
- Все 277 открытых позиций раннего скана оставлены историческими: скан не записывал сведения об обязательствах и полноте поиска фандеров, требуемые v6. Их исходные выводы не переписаны. На текущих рейтингах остаются четыре более новых примера; архив доступен в Explore.
- Пояснения, README и социальные картинки обновляются вместе с правилами. Старые версии результатов не объявляются свежей проверкой адреса.

## Границы вывода

Тесты проверяют правила и их согласованность с данными, а не точность классификации реальных намерений трейдеров. Независимой размеченной выборки нет. Book — наблюдение двусторонней активности, а не доказательство отсутствия направленной ставки. Покрытие сравнивает USD-стоимость и не моделирует полностью долговые обязательства, collateral/liquidation, дельту производных токенов и перенос экспозиции между площадками. Внешние биржи, OTC и несвязанные адреса остаются невидимыми. Реестр активов ограничен; для полноценной поддержки HIP-3 нужна проверенная карта базовых активов.

Заявлять «ошибок гарантированно нет» или «реальная стратегия кошелька определена точно» по результатам этой проверки нельзя.
