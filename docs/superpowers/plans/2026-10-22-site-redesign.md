# Site redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-skin and restructure the Bet or Book site into the four screens of the owner's handoff (Check, Reading, Explore, Saved) with one visual system, keeping every real datum, call and behaviour of the current site.

**Architecture:** The page stays one static HTML document driven by `web/app.js` (a show/hide state machine on `hidden` attributes and `body` classes). The redesign replaces the stylesheet and the markup skeleton, keeps every element id the scripts use (a contract test pins this), and adds one small piece of state: the current screen and, for a reading, the screen it was opened from (`body[data-screen]`, `body[data-from]`), which drives the header tabs, the breadcrumb and the "Back to ..." button. The reading card becomes six numbered sections inside the existing `#card`.

**Tech Stack:** Plain HTML/CSS/JS (no framework, no bundler beyond `scripts/build-web.ts` for `app.min.js`), Cloudflare Worker serving the page and fonts, vitest. Fonts: Geist and Geist Mono, self-hosted.

**Spec:** `C:\Server\bet_or_book\docs\superpowers\specs\2026-10-20-redesign-and-nansen-removal-design.md` (lives on branch `remove-nansen` in the other checkout until the branches meet). ## Review Focus

Failure modes the spec implies that no single screen's happy path exercises (each gets its test or its checked state in the task named):

1. Reading sections that have no content must disappear, and the visible ones keep consecutive numbers (CSS counters), never an empty numbered row: a reading without a coverage illustration, without a previous reading, without blind-spot notes, a degraded reading with the source banner, a historical (older rules) reading, a reading whose positions have no `positionsVenues` (Task 5).
2. Narrow screens (375 px and 768 px): header tabs fit without overflow, hero input and button wrap, cards go to one column, the Evidence stat panel wraps as 4x1 or 2x2 and never 3+1, no horizontal page scroll with a long wallet address or a long amount (Task 7).
3. Keyboard and assistive tech: tabs are real links or buttons with `aria-current`, the Share menu opens with Enter or Space, closes on Escape and on outside click and returns focus to its button, the segmented Explore tabs keep `aria-pressed`, the breadcrumb is a `nav` with `aria-label`, focus lands on the new screen's H1 after navigation (Tasks 3, 5, 6).
4. Empty, loading and failure states keep working: Saved with nothing saved (empty state in the CTA panel), Explore while the gallery loads and when it fails, the check's error status and the slow-check line, the address-choice picker, the guess game, the "claim checker" (Task 4, 5, 6).
5. Navigation state: opening a reading from Explore then pressing Back returns to Explore; the highlighted tab on Reading is the screen it came from; a shared `/?s=<id>` link opened cold has `from` = Check; every navigation scrolls to the top (Task 3).
